## 1. Обзор

В компании эксплуатируется локальный аналитический портал собственной разработки, на котором публикуются дэшборды Tableau. Портал содержит обширное меню разделов и дэшбордов — пользователи тратят время на поиск нужных данных и нередко не находят их вовсе.

Проект — ИИ-ассистент в виде чат-виджета, встроенного в интерфейс портала. Пользователь пишет запрос в свободной форме («покажи выручку с начала года»), ассистент:

1. отвечает в чате кратким деловым аналитическим выводом с ключевыми цифрами;
2. параллельно автоматически открывает на портале нужную страницу / вкладку / дэшборд.

## 2. Проблема

- Навигация по порталу требует знания структуры меню и названий дэшбордов.
- Не все пользователи регулярно работают с порталом — «разовые» потребители данных (руководители, смежные департаменты) не помнят, где что лежит.
- Поиск по меню не отвечает на вопрос по существу: пользователь хочет не страницу, а ответ («как дела по выручке?») и быстрый переход к деталям.

## 3. Цели и метрики успеха

**Цели:**

- Снизить порог доступа к данным портала до одного текстового запроса.
- Сократить время поиска нужного дэшборда с минут до секунд.
- Дать пользователю готовый короткий вывод, а не только ссылку на виз.

**Метрики успеха (предлагаемые):**

| Метрика | Целевое значение |
|---|---|
| Доля запросов, распознанных с первого раза | ≥ 85% |
| Время от отправки запроса до открытого дэшборда | ≤ 5 сек |
| Доля сессий с повторным использованием ассистента | ≥ 40% |
| Снижение обращений «где найти отчёт X» в поддержку аналитики | −50% за квартал |
| CSAT по ответам ассистента (оценка в чате) | ≥ 4.2 / 5 |

## 4. Целевая аудитория

- Руководители и менеджеры среднего звена — основные потребители управленческих показателей.
- Аналитики и специалисты департаментов — регулярные пользователи дэшбордов.
- Смежные сотрудники, работающие с порталом эпизодически.

## 5. Область проекта

**Входит (In scope):**

- Чат-виджет, закреплённый в правом нижнем углу всех страниц портала.
- Понимание запросов на естественном языке (русский) о показателях компании.
- Генерация краткого аналитического вывода по запрошенным метрикам.
- Автоматическое открытие релевантного дэшборда Tableau в рабочей области портала.
- Кнопка «Открыть дэшборд» в сообщении ассистента (повторный переход).
- Подсказки-чипы с примерами запросов и fallback при нераспознанном запросе.

**Не входит (Out of scope, на текущую фазу):**

- Изменение данных и запись в источники (read-only сценарии).
- Свободная аналитика «глубокого исследования» (ad-hoc срезы данных в чате без открытия дэшборда).
- Голосовой ввод.
- Мобильное приложение (веб-портал адаптируется, отдельного приложения нет).
- Мультиязычность (первый язык — русский).

## 6. Функциональные требования

### FR-1. Распознавание намерения (intent routing)

Система определяет, о каком разделе / дэшборде / метрике идёт речь, включая синонимы и разговорные формулировки («рентабельность», «лиды», «филиалы», «п&л», «текучка»).

- В прототипе реализовано сопоставлением по словарю ключевых слов с взвешиванием.
- В целевой версии — классификация намерения средствами LLM (function/tool calling) по каталогу дэшбордов.

### FR-2. Аналитический вывод в чате

На распознанный запрос ассистент формирует короткий деловой вывод по шаблону:

- значение показателя YTD (с начала года);
- динамика к аналогичному периоду прошлого года (АППГ), в %, с качественной оценкой («уверенный рост», «стабильный уровень», «небольшое снижение»);
- выполнение плана, где план существует;
- 1–2 предложения интерпретации (что драйвит динамику, где зона внимания).

Пример тона (из прототипа):
> «Выручка YTD: 8 214 млн ₽ — **+2,1%** к аналогичному периоду 2025 г. (умеренный рост с начала года). Выполнение плана — 95,3%».

### FR-3. Открытие дэшборда

- При распознанном намерении портал автоматически переключается на соответствующую страницу / вкладку / дэшборд.
- Открытый из чата дэшборд визуально подсвечивается (анимация-вспышка рамки), чтобы пользователь заметил смену контекста.
- В сообщении ассистента всегда присутствует кнопка «Открыть дэшборд» для повторного перехода.
- Целевая реализация: навигация по URL-вью Tableau через Embedding API v3 внутри iframe рабочей области портала.

### FR-4. Fallback и подсказки

- Если намерение не распознано, ассистент не «молчит» и не фантазирует: предлагает список доступных направлений кнопками-чипами.
- На старте диалога показываются 3–4 примера запросов, чтобы обучить пользователя формулировкам.

### FR-5. Диалог в рамках сессии

- История диалога сохраняется в течение сессии (контекст уточняющих вопросов: «а по регионам?»).
- Индикатор «печатает…» во время формирования ответа.

## 7. Требования к UX

- **Расположение:** виджет закреплён справа снизу на всех страницах портала (свёрнут — круглая кнопка с индикатором доступности; развёрнут — панель ~390×600 px).
- **Стиль общения:** деловой, краткий, без «воды». Сначала цифры, затем интерпретация. Эмодзи не используются.
- **Поведение панели:** разворачивание/сворачивание без потери истории диалога; панель не перекрывает критичные элементы дэшбордов.
- **Доступность:** клавиатурная навигация (Enter — отправка), контраст по корпоративному стандарту.

## 8. Архитектура

### 8.1. Текущее состояние (прототип)

Единый HTML-файл (`ai-assistant-portal.html`), самодостаточный:

- макет портала: меню, 6 демо-дэшбордов (Продажи и выручка, P&L/EBITDA, Продажи по регионам, Клиенты, HR, Маркетинг) с KPI-карточками и графиками «год к году» на встроенном SVG;
- чат-виджет справа снизу: NLU на ключевых словах, генерация вывода из встроенных демо-данных, автопереход к дэшборду с подсветкой;
- данные синтетические, но правдоподобные (помесячные ряды 2026 vs 2025, планы).

Прототип предназначен для демонстрации сценариев и UX стейкхолдерам.

### 8.2. Целевая архитектура

```
┌──────────────────────────────────────────────────────┐
│  Аналитический портал (собственная разработка)       │
│                                                      │
│  ┌────────────────────────┐   ┌──────────────────┐   │
│  │ Рабочая область        │   │ Чат-виджет       │   │
│  │ (iframe: Tableau       │   │ (JS-модуль,      │   │
│  │  Embedding API v3)     │   │  правый нижний   │   │
│  │                        │   │  угол)           │   │
│  └─────────▲──────────────┘   └────────▲─────────┘   │
│            │ навигация по URL-вью      │ HTTPS       │
└────────────┼───────────────────────────┼─────────────┘
             │                           │
┌────────────┴──────────┐   ┌────────────┴─────────────┐
│  Tableau Server       │   │  Бэкенд ассистента       │
│  (REST API, визы)     │   │  - оркестрация диалога   │
└───────────────────────┘   │  - каталог дэшбордов     │
                            │  - tool-calling к LLM    │
┌───────────────────────┐   │  - аналитический слой    │
│  Витрина DWH          │◄──┤    (YTD, АППГ, план)     │
│  (KPI, агрегаты)      │   └────────────┬─────────────┘
└───────────────────────┘                │
                            ┌────────────┴─────────────┐
                            │  LLM (OpenAI-совместимый │
                            │  API: корп. шлюз /       │
                            │  локальная модель)       │
                            └──────────────────────────┘
```

**Принципы:**

- **Модельно-агностично:** слой LLM за абстракцией OpenAI-совместимого API — замена модели не трогает остальной код.
- **LLM не считает:** все числа для вывода ассистент получает из аналитического слоя (витрина/Tableau REST API) через инструменты; модель только формулирует текст по полученным цифрам. Это исключает галлюцинации в показателях.
- **Виджет — отдельный JS-модуль**, подключаемый на любую страницу портала одной строкой; общается с бэкендом по REST/WebSocket.
- **Read-only:** ассистент только читает данные и управляет навигацией.

### 8.3. Интеграция с Tableau

- Навигация: виджет шлёт команду → рабочая область открывает URL-вью нужного дэшборда (Embedding API v3, `<tableau-viz>`).
- Цифры для вывода: предпочтительно из витрины DWH (быстро, контролируемо); как вариант — Tableau REST API / Get Data визов.
- Каталог дэшбордов (название, раздел, URL-вью, ключевые слова, доступные метрики) ведётся в бэкенде и синхронизируется с публикациями на сервере.

## 9. Данные

**Сейчас (прототип):** встроенные демо-данные — помесячные ряды за янв–окт 2026 и аналог 2025, планы YTD.

**Цель:** аналитический слой бэкенда отдаёт по каждой метрике:

- YTD текущего года и АППГ;
- помесячный ряд (текущий год / прошлый);
- план YTD и отклонение (где применимо);
- метаданные: единицы измерения, дата обновления, источник.

Дата обновления и источник показываются в интерфейсе (как в прототипе: «Обновлено: 07.11.2026, 06:00 · источник: витрина DWH»).

## 10. Нефункциональные требования

- **Производительность:** ответ ассистента ≤ 5 сек (p95); аналитические агрегаты — предрасчёт в витрине, а не запросы к Tableau в реальном времени.
- **Безопасность:** работа во внутреннем контуре; аутентификация пользователя портала проксируется в ассистента; права доступа к дэшбордам соответствуют правам пользователя (ассистент не открывает и не цитирует то, что пользователю недоступно); запросы и ответы логируются для аудита.
- **Приватность данных:** если выбран внешний LLM — через корпоративный шлюз; числа в промпт передаются только уже вычисленные, без персональных данных.
- **Надёжность:** деградация без LLM — fallback на словарный роутинг (как в прототипе) с чипами-подсказками.

## 12. Открытые вопросы

1. Какая LLM будет использоваться: корпоративный шлюз к облачной модели или локально развёрнутая (Ollama/vLLM)? Влияет на требования к инфраструктуре и приватности.
2. Источник аналитических агрегатов: отдельная витрина DWH (предпочтительно) или извлечение из визов Tableau?
3. Кто владелец каталога дэшбордов и процесс его актуализации при публикации новых визов?
4. Нужна ли персонализация ответов по роли пользователя (например, CFO видит другой набор метрик)?
5. Хранение истории диалогов: срок, доступ, использование для улучшения качества?
6. Требования ИБ к логированию запросов (чувствительность показателей)?

## 13. Приложение: состав прототипа

Файл: `ai-assistant-portal.html` (единый HTML, без внешних зависимостей).

Реализованные демо-дэшборды и покрываемые темы запросов:

| Дэшборд | Метрики | Примеры распознаваемых запросов |
|---|---|---|
| Продажи и выручка | Выручка YTD, число сделок, план | «покажи выручку с начала года», «продажи», «выполнение плана» |
| Финансовый результат (P&L) | EBITDA, рентабельность по EBITDA | «какая EBITDA», «прибыль», «маржинальность» |
| Продажи по регионам | Выручка по 6 регионам, YoY по каждому | «продажи по регионам», «филиалы», «Москва» |
| Клиентская база | Активные клиенты, новые клиенты | «клиенты», «отток», «новые клиенты» |
| Персонал (HR) | Численность FTE, текучесть | «текучесть кадров», «численность», «найм» |
| Маркетинг и воронка | Лиды, конверсия в сделку | «лиды», «конверсия», «воронка» |

Поведение виджета в прототипе соответствует FR-1…FR-5 (словарный NLU вместо LLM).
